# R3 Bundling edit pair (PTP)

> Reference page written by code from the pipeline. Rebuilt on every change; do not edit by hand.

## What it checks
A component code (column 2) is billed together with the comprehensive code that already includes it (column 1), for the same member, provider and date.

## Threshold
Any matching pair on the same member, provider and service date. The component claim is flagged.

## Reference table
637 code pairs: 500 official CMS NCCI pairs (v32.3, file 1) plus 137 pairs derived from code definitions, which are not from the CMS table. Loaded by `backend/pipeline/reference.py`. See [[REG-NCCI]].

## Data used
- `member_id`
- `provider_id`
- `procedure_code`
- `service_datetime`
- Defined in: [[data_claims]]

## Known exceptions
- Pairs with modifier indicator 1 are payable when a supported modifier is on the claim (modifiers are not in this data)
- Tests drawn on separate dates that look same-day because of a date entry error

## Patterns it supports
- [[unbundling]] | Unbundling

## Regulatory background
- [[REG-NCCI]] | CMS National Correct Coding Initiative (NCCI)
